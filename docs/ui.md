# 主题工坊面板

**0.3 面板源码**：以 [设计契约 §3–5](DESIGN.md#3-生效通道)和[操作指南](../README.md)为准。点选或编辑触发预览；页脚常驻撤销／重做、还原和保存为文件。主题首张为默认；风格首张为无风格，选中的强度和选项在列表底部。窄栏允许完整的风格名折行。作品管理在各卡片的垃圾桶入口；「⋯」里可以查卸载前的还原步骤。缺少原始备份时，状态行提供只读的手动恢复方法。

以下保留 **0.1 RC2 的历史设计与证据**，其中「应用」「改为长期使用」和旧引导不再是 0.2 界面操作。

## 方向约定

- **主张**：这是可编辑的 OpenChamber 小样，不是先选色、另找验收画布的配置表。点小样里的实际组件，进入它的精修项。
- **外观**：继承宿主中性色、字体、细线和小圆角；工作台表面保持克制，把色彩留给小样和成对的主题样本。宿主调坏时编辑控件仍然可读。
- **顺序**：先看当前作品与生效状态，再看样本，然后按「选主题 → 选风格 → 调色 → 精修 → 查看搭配」深入。应用在页脚固定，而不是藏在菜单中。
- **首屏**：单行作品名和明暗、独立的连接状态、可折叠的聊天小样、五标签、首个内容组与操作栏。宽栏增加内容列而不是拉长控件。

## 契约对接（工作线 U → I1）

UI 字典放 `src/i18n/ui.zh.mjs` 和 `ui.en.mjs`，不占用 I1 的 `core.*`。下面需要 I1 对接的能力详见 `DESIGN.md` §6；UI 不会自行以浏览器权限绕过宿主。

## 界面与组件

| 区域 | 查找与操作 |
| --- | --- |
| 固定页眉 | 点名称或笔编辑；浅／深只切换**正在编辑**的版本。状态行旁就能试穿、还原原主题、准备长期使用、去外观选用或重试。关掉引导仍可使用。菜单另外提供复制／导入／导出和清理说明。 |
| 快速上手 | 非弹窗三步：挑一套、整窗应用、长期使用。首次可暂借时，行内说明同服且使用同一内置主题的其他窗口和设备也会变色、还原即恢复。关闭引导不隐藏说明。 |
| 迷你预览 | 由 `themeToCssVariables` 着色，沿用宿主边线、消息和状态的用色关系。每个样本按其主要颜色定位到一行精修，键盘也能打开。它不会放大成可编辑的宿主，也不会显示宿主没有的效果。 |
| 主题 | 11 套浅深配对缩略图、已识别可编辑的当前主题、我的作品、31 组宿主配色（折叠）、本机图片、随机与导入。缩略图突出实际选中行、气泡、按钮、语法色；每一版另有五色签名。图片在本地 Canvas 缩到 256 × 256，再交给共享取色算法。 |
| 风格 | 17 种配方和无风格，缩略图以完整强度显示区别，合成当前微调与精修；强度和专属选项是列表底部的常驻条，精修覆盖优先。 |
| 调色 | 三种子色、代码配色策略、全局／分组五旋钮、保护状态色相／代码区分、浅深联动与双向生成、可读性检查和修复前后色片。 |
| 精修 | 用字段表做分组、常用／进阶／专家、双语搜索与只看已改；隐藏未渲染项。取色器在行内，含饱和明度色面、色相、透明度、HEX、高级 CSS、最近／主题色和对比度；「跟随自动」清除当前覆盖。 |
| 搭配 | 开头说明主题无法调整的外观。提供界面与等宽字体试读、字号／字重／间距／聊天宽度／布局动效建议；只有快照提供的数据才作为当前值。Canvas 检测是本机字形度量启发式，不枚举字体、不下载字体、不改设置。 |
| 固定页脚 | 实时、撤销、重做、还原改色、另存。可直接改变整窗时主操作为「应用」；否则先准备主题并显示手动选用指引，无文件权限则复制 JSON。页脚还原回到本次明暗的上次应用；状态行「还原原主题」会退出暂借。 |
| 任务对话框 | 另存与导出选择浅／深／两者，按成功文件显示路径与复制；导入支持拖入、选文件、粘贴，区分格式错误、被忽略的键和 VS Code 主题；剪贴板拒绝时可手动选中 JSON；清理指引不擅自删除文件。 |

预览域和工具栏域分开：原生气泡用 `--chat-user-message-bg`；代码取 `--syntax-*`，工具预览 diff 行取 `--tools-edit-*-bg`，不把编辑器 diff 栏色做成聊天工具背景。选中行与状态色分别走真实用途；未把 `chat.background` 当作聊天画布。尺寸、圆角和线宽统一，打样有变色，但不会画出宿主不支持的粗边、硬影或直角。对照 `presets-final-focus-dark.png`、`presets-final-overview.png` 和 `desktop-before.jpg` / `desktop-after.jpg` 核过结构与颜色关系；布局是工坊自己的缩尺样本，不复用截图。高级输入支持独立的 CSS 颜色，不执行宿主变量引用或载入外部资源。

工具栏从宿主快照取前景、表面、主色、字族和圆角；交给 `chromePalette` 检查对比。正文、次要文字和状态文字按实际的底、抬升、悬停和选中状态调整到至少 4.5:1，焦点和控制线至少 3:1。不能读的宿主色用深／浅兜底；极高彩度底色只保留其色调作为工坊表面染色。字体和圆角限制在控件可用范围内。工具栏的纠偏不写回作品，也不作用于迷你预览。透明色对比先合成底色；可被浏览器解析但核心无法精确度量的高级色在取色器按浏览器采样的 sRGB 近似，体检仍尊重核心的未测项目。

## 键盘、屏幕阅读和动作

- `Tab` / `Shift+Tab` 依可见顺序移动；顶部有跳到编辑区的链接。标签用 `← → Home End` 切换；`Enter` 或 `Space` 可操作聚焦的按钮、开关、字段。预览被折叠时不进入其样本。
- 聚焦范围滑杆后用方向键、`Home`、`End`；鼠标双击风格／调色滑杆回默认。键盘可展开色面替代操作，用「彩度与亮度」两条滑杆代替拖动指针；Hue/Opacity 也有独立范围控件。
- 在 HEX／CSS 中 `Enter` 提交；无效时保留输入并读出提示。颜色面拖动用 pointer capture，输入合并到逐帧更新，释放时只提交一笔撤销事务。对比失败和成功用文字／数字标识，不只靠颜色。
- `Ctrl/Cmd+Z` 撤销、`Ctrl/Cmd+Shift+Z` 或 `Ctrl+Y` 重做；在文本字段内不拦截浏览器的文本撤销。`Escape` 关操作菜单／对话框；关闭对话框后恢复焦点。另存名称内 `Enter`、粘贴区 `Ctrl/Cmd+Enter` 可确认；三个文件动作都不依赖原生表单提交（宿主沙箱仅 `allow-scripts`）。
- Chrome 仅在实现 `EyeDropper` 时显示屏幕取色按钮；iframe 或用户取消时可继续输入颜色。尊重减少动效以及高对比模式的系统设置。

## 独立验证入口

```bash
node --test src/ui/model.test.mjs
UI_PLAYWRIGHT=/path/to/playwright/index.mjs node scripts/ui-verify.mjs --screens
node scripts/ui-serve.mjs --fake-only
```

`ui-serve` 只在 `127.0.0.1` 绑定随机端口；`?scenario=conflict&locale=zh-CN&mode=dark` 切假 Studio 场景，也可调用 `window.__uiDev.setScenario('waiting')` 当场切换。去掉 `--fake-only` 以启用 `?core=real`（I1 真实 Studio＋内存宿主）和 `/sandbox`（仅授予 `allow-scripts` 的 iframe）。`--sandbox-only` 只跑沙箱回归。设 `UI_STYLE=/path/to/style.css` 可在替换 `panel/style.css` 前先核对候选包的样式；不设时读仓库根目录的样式。可重复截图脚本需现有 Playwright Chromium、Bun 和 ImageMagick；运行时不引入 npm UI 库，也不会触碰已运行的 OpenChamber。

### 中文原生宿主复验

在仓库根目录构建后，使用专用隔离桌面、真实右侧栏分隔条和真实文件能力，不接入用户在用的窗口：

```bash
node scripts/dev-host.mjs start --name u-ui-review --desktop --default-data-dir --extension "$PWD"
node scripts/ui-host-verify.mjs u-ui-review
node scripts/dev-host.mjs stop --name u-ui-review
```

本地生成的 `docs/research/evidence/ui-host-{320,420,720}.jpg`：首次打开 → 整窗应用 → 改色 → 还原改色 → 另存 → **另存后不重新应用、直接改色** → 导入；最后还原原主题后，另拍风格页及其「做不到」。测试比较宿主本身的 CSS，检查重开无遗留试穿提示、另存实际两份文件后仍能实时改色、重导隔离宿主磁盘的原生 JSON 时整窗也跟着变；不以插件小样代替宿主证据。看图复核发现：320 px 的新行内动作曾误用浏览器默认按钮边框，与宿主控件不协调；现改为无边框的工坊文字动作，保留对比、点击高度和焦点。引导中的「整窗应用」也只在宿主已确认时打勾。120 px 无名配色签名的单独证据为 `ui-signatures-120.jpg`。

正式包在隔离中文桌面 2.8.0 通过：三个宽度都是原生拖拽实测值。整窗强调色为 `#b35017` → `#006579`（应用）→ `#176eac` → `#006579`（还原颜色）→ `#8e3c80`（另存后实时改色，仍显示已应用与草稿未应用）→ `#006579`（导入）→ `#b35017`（还原原主题）；只试配方时宿主未变色，0 渲染错误。三张拼图合计 863,955 B，均已看图核对。安装副本与根目录四个 `panel` 资产（主脚本、内置图册、CSS、入口 HTML）在验收前后逐字节一致。

## 验证与性能

Chromium 151.0.7922.34 本机 headless：60/60 布局、20/20 状态、25+ 真实 Studio＋内存宿主交互通过；无浏览器错误、无外部请求。`allow-scripts` iframe 另存返回两条路径、导出一条，粘贴导入与剪贴板拒绝的手动 JSON 回退通过。纯 UI 逻辑测试 10/10；指定上游 v2.8.0 副本后，整个 `node --test` 63/63。

冷首屏（导航到第二个渲染帧，12 次，假 Studio）中位数 80 ms、P95 155.5 ms。真实 Studio＋内存宿主中，风格／调色／取色拖动单次更新 P95 分别 9.5／3.7／4.1 ms；所测 `requestAnimationFrame` 间隔 P95 依次为 16.8／16.7／16.8 ms。前一组测 Studio 到小样（取色含对比度），不含整窗写盘／同步或浏览器全部绘制开销。正式 IIFE 542,349 B（gzip 138,834 B）；CSS 44,829 B；内置图册按需加载，140,262 B。

未在多个物理刷新率、真实屏幕阅读器／高对比系统、实机 EyeDropper 取色或其他浏览器重复跑矩阵。整窗反映和恢复以隔离宿主证据为准，不从上述内存宿主帧率推断。
